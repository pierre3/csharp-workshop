## Span<T>とMemory<T>について

https://learn.microsoft.com/ja-jp/dotnet/fundamentals/runtime-libraries/system-span%7Bt%7D

### `Span<T>`
`Span<T>` は、.NET におけるメモリ管理の効率化を目的とした構造体で、特定のメモリ領域を参照するために使用されます。

#### メリット
- 配列や文字列の一部をコピーせずに参照できるため、メモリ割り当てを削減し、処理速度を向上させます。
- `Span<T>` の型は ref struct で、常にスタック上に存在し、GC（ガベージコレクション）の影響を受けません。
- `Slice()`メソッドを使うことで、配列や文字列の一部を簡単に取得できます。

### デメリット・注意点
- ヒープに格納できないため、クラスのフィールドとして使用できません。
- `Span<T>` は、非同期メソッドやラムダ式のキャプチャに使用できません。
- GCの影響を受けないが、参照元のメモリが解放されると無効になるため、スコープ管理が必要です。

### `ReadonlySpan<T>`
`ReadOnlySpan<T>` は、`Span<T>` の読み取り専用バージョンで、データの変更を防ぎます。値を変更しないケースでは、`ReadOnlySpan<T>` を使用することが推奨されます。

### `Memory<T>`

`Memory<T>` は、`Span<T>` の機能を拡張したもので、ヒープ上に格納できるため、クラスのフィールドとして使用できます。

#### `Span<T>` と `Memory<T>`の違い
`Span<T>` と `Memory<T>` はどちらも .NET におけるメモリ管理を効率化するための型ですが、いくつかの重要な違いがあります。

| 特性 | `Span<T>` | `Memory<T>` | 
| --- | --- | --- |
| メモリの配置 | スタックのみ | ヒープにも配置可能 | 
| 非同期処理 | 使用不可（スタック上にあるため） | 使用可能（ヒープに配置できるため） | 
| 型の種類 | ref struct（ヒープに置けない） | struct（ヒープに置ける） | 
| スライス機能 | Slice() で部分参照可能 | Slice() で部分参照可能 | 
| 用途 | 高速なメモリ操作（短期間の処理向け） | 長期間のメモリ管理（非同期処理向け） | 


使い分け
- Span<T> は スタック上 に配置されるため、短期間のメモリ操作 に適しています。例えば、文字列の一部を処理する場合や、スタックメモリ (stackalloc) を活用する場合に便利です。
- Memory<T> は ヒープに配置可能 なので、非同期処理 でメモリを保持する必要がある場合に適しています。例えば、非同期メソッド (async) 内でデータを保持する場合に使用されます。


#### `T[]`と`Memory<T>`の違い

| 特性 | 配列 (T[]) | Memory<T> | 
| --- | --- | --- |
| メモリの配置 | ヒープ上 | ヒープ上 | 
| 非同期処理 | 使用可能 | 使用可能（特に async メソッド内で有用） | 
| スライス機能 | ArraySegment<T> で部分参照可能 | Slice() で部分参照可能 | 
| 型の種類 | class | struct | 
| パフォーマンス | 通常のメモリ管理 | Span<T> と組み合わせることで効率的なメモリ管理が可能 | 
| 用途 | 一般的なデータ格納 | 非同期処理やメモリ管理の最適化 | 


配列ではなく Memory<T> を使う理由
- 非同期処理での安全なメモリ管理
  - Memory<T> は Span<T> と異なり、ヒープに配置できるため、非同期メソッド (async) で安全に使用できます。
- 柔軟なメモリ管理
  - Memory<T> は Slice() を使って部分的なデータを参照できるため、メモリの再利用が容易です。
- Span<T> との連携
  - Memory<T> から Span<T> を取得することで、効率的なメモリ操作が可能になります。


## ヒープとスタック

C# における スタック と ヒープ の違い

### スタック (Stack)
- メモリ管理: LIFO (Last In, First Out) の方式で管理され、関数の呼び出し時に自動確保、関数終了時に自動解放される。
- 用途: ローカル変数、関数の引数、Span<T> のような スタック専用メモリ。
- 速度: 高速（連続したメモリ領域に配置されるため）。
- サイズ制限: 固定サイズ（通常、数 MB）。
- ガベージコレクション: 影響を受けない（自動管理される）。

### ヒープ (Heap)
- メモリ管理: プログラム実行中に動的にメモリを手動確保し、GC により不要なオブジェクトが自動解放される。
- 用途: new によるオブジェクトの作成、大規模データ構造 (List<T>, Dictionary<TKey, TValue> など)。
- 速度: スタックより遅い（メモリの断片化が発生するため）。
- サイズ制限: なし（システムの限界まで拡張可能）。
- ガベージコレクション: 影響を受ける（GC が不要なメモリを回収）。


| 項目 | スタック | ヒープ | 
| --- | --- | --- |
| メモリ確保 | 自動 | 動的 (new で確保) | 
| 解放 | 関数終了時に自動 | GC により自動解放 | 
| 速度 | 高速 | 低速 | 
| サイズ制限 | あり (固定) | なし (動的) | 
| 用途 | ローカル変数、関数の引数 | オブジェクト、大規模データ | 
| ガベージコレクションの影響 | なし | あり | 

## `ref struct` とは
ref struct は、C# における特殊な構造体で、スタック上にのみ配置される という制約を持っています。これは、メモリ管理の最適化やパフォーマンス向上のために導入されました。

| 特性 | ref struct | 通常の struct | 
| --- | --- | --- |
| メモリの配置 | スタックのみ | スタックまたはヒープ | 
| ヒープへの配置 | 不可 | 可能 | 
| 非同期処理 (async) での使用 | 不可 | 可能 | 
| インターフェースの実装 | C# 13 以前は不可、C# 13 以降は可能 | 可能 | 
| 配列の要素として使用 | 不可 | 可能 | 
| ボックス化 (boxing) | 不可 | 可能 (object や ValueType に変換可能) | 


### 利点
- パフォーマンス向上
  - ref struct は ヒープに配置されない ため、ガベージコレクション (GC) の影響を受けず、高速なメモリ管理が可能です。
- メモリの安全性
  - ref struct は ヒープに逃げない ため、意図しないメモリリークを防ぐことができます。
- Span<T> の基盤
  - Span<T> や ReadOnlySpan<T> は ref struct であり、効率的なメモリ操作を実現しています。

### 制約
- ヒープに配置できない → クラスのフィールドとして ref struct を持つことはできません。
- 非同期 (async) メソッドで使用不可 → ref struct はスタック上にあるため、非同期処理のスコープを超えるとメモリ破損のリスクがあります。
- 配列の要素として使用不可 → ref struct を T[] の要素として持つことはできません。


### `Span<T>`や`Memory<T>`のを利用すべきケース

Span<T> を使うことで、メモリ効率やパフォーマンスを向上できる場面が多くあります。以下のような操作は Span<T> に置き換えることでメリットが得られます。

| 操作 | 置き換え前 | 置き換え後 (Span<T> を使用) | メリット | 
| --- | --- | --- | --- |
| 部分配列の取得 | array.Skip(n).Take(m).ToArray() | array.AsSpan().Slice(n, m) | メモリコピー不要で高速 | 
| 文字列の部分取得 | str.Substring(n, m) | str.AsSpan().Slice(n, m) | メモリ割り当てを削減 | 
| バイナリデータ処理 | byte[] を直接操作 | Span<byte> を使用 | メモリコピーを減らし、効率的に処理 | 
| スタックメモリの活用 | new int[100] | stackalloc int[100] | ヒープを使わずに高速処理 | 
| アンマネージメモリの操作 | Marshal.AllocHGlobal で確保 | Span<T> を使用 | 安全なメモリ管理が可能 | 
| 配列の一部を変更 | ArraySegment<T> を使用 | Span<T> を使用 | より柔軟で高速な操作が可能 | 
| 非同期処理でのメモリ管理 | byte[] を使用 | Memory<T> を使用 | 非同期処理でも安全にメモリ管理 |
